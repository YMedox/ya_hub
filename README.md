# Алиса в вашем умном доме. Или Маруся. Или Салют. Универсальный шлюз для подключения голосовых помощников к умным домам или умным устройствам.

Интересен тем, кто предпочитает иметь независимый от вендора умный дом, например на базе HomeAssistant (https://www.home-assistant.io/) или OpenHAB (https://www.openhab.org/) или на базе устройств собственной разработки. И при этом хочет иметь управляемый коннектор к голосовому помощнику,  не полагаясь на addon`ы к указанным умным домам. Более того, можно организовать работу вообще без локального умного дома и без облачного умного дома от вендора. Это можно сделать, например, на базе Zigbee-устройств и локально установленного сервиса zigbee2mqtt (https://www.zigbee2mqtt.io/). В этом случае шлюз может работать напрямую с zigbee2mqtt, а в качестве интерфейса умного дома можно использовать приложение «Умный дом» от Яндекса. Аналогично с zwave-устройствами и сервисом zwave2mqtt (https://github.com/OpenZWave/Zwave2Mqtt?ysclid=mocsvclxxl590485879).

Шлюз работает с навыком типа «умный дом» Яндекса (https://yandex.ru/dev/dialogs/smart-home/doc/ru/), а также с аналогичным навыком VK (https://help.mail.ru/marusia/smart_home/provider/), работающим по протоколу Яндекса. Кроме этого, позволяет выступать в качестве бэкенда для универсальных навыков Алисы (https://yandex.ru/dev/dialogs/alice/doc/ru/development) и смартапов Салюта (https://developers.sber.ru/portal/virtual-assistants-salute).
Таким образом, для управления умным домом можно использовать умные колонки с Алисой (Яндекс), Салютом (Сбер) или Марусей (VK).

Все универсальные умные дома  типа OpenHAB или HomeAssistant имеют свой API, который позволяет получать статусы и управлять подключенными к умному дому устройствами. Аналогично и независимые умные устройства, например самодельные на базе Arduino/ESP8266/ESP32/STM. У всех разные протоколы, и разные транспорты: кто-то работает по REST API, кто-то по MQTT.
В свою очередь навыки голосовых помощников типа «умный дом» имеют свой API, универсальные навыки (Алиса, например) также имеют формализованный API. Таким образом, задача состоит в трансформации протокола облачного умного дома, в котором «живет» голосовой помощник и протокола своих устройств. Для этого придется также связать учетные записи облачного умного дома и описываемого шлюза по протоколу OAuth 2.0, для чего потребуется web-форма авторизации. Все эти задачи и решает описываемый шлюз.

Шлюз написан под Linux на C++. Использует в качестве интерфейса библиотеку Wt (https://www.webtoolkit.eu/) версии 4.10.3. Кроме интерфейса, библиотека Wt используется для работы с http-запросами и Json-объектами. Модули Wt::Dbo, Wt::Auth не используются по внутренним историческим причинам. В качестве базы данных используется MySQL и С++-коннектор xdevapi версии 8.3.0 (https://downloads.mysql.com/archives/c-cpp/). Вероятно, всё будет работать и на более поздних версиях библиотек, но это не проверялось. Для работы потребуется также доменное имя и сертификат, все соединения с облачными сервисами только по https.

Шаги для получения результата типа такого: «Алиса, закрой штору на кухне» или такого: «Алиса, включи ночник в спальне». На примере умного дома Яндекс с Алисой:
1. Установка glib-2.0, если не установлена на машине, включая заголовочные файлы. Не требователен к версии библиотеки. Возможной командой для deb-дистрибутивов может быть sudo apt-get install libglib2.0 libglib2.0-dev.
2. Установка Wt. Делается это сборкой из исходников и сложностей не вызывает. На сайте библиотеки есть подробные инструкции. Шлюз написан на версии 4.10.3.
3. Установка MySQL С++-коннектора. Для распространенных ОС есть готовые пакеты, есть и возможность сборки из исходников, что может оказаться сложно. Из российских ОС устанавливается на Red OS без особых сложностей, на Alt Linux — с отдельной ручной установкой заголовочных файлов. Подразумевается, что сам MySQL сервер установлен где-то, куда будет доступ у шлюза.
4. Регистрация доменного имени, получение ssl-сертификатов. Например Let`s encrypt. В интернете много статей о том, как выпускать и обновлять сертификаты.
5. Клонирование репозитория functions, в котором содержатся линкуемые со шлюзом библиотеки:
   
    git clone https://github.com/Ymedox/functions

    В тот же каталог, куда клонирован functions, клонируем и исходники самого шлюза:

    git clone https://github.com/Ymedox/ya_hub

5. Заполнение конфигурационного файла ya_hub.conf. Он подробно закомментарен. Важно правильно заполнить секции [Client_ids]. В шаблонном файле сделаны примеры для разных интеграций.
6. Создание базы данных, импорт описаний таблиц и базовых данных из файла ya_hub.sql. Предполагается, что MySQL сервер установлен и к нему есть доступ с правами на создание базы данных и пользователя. В среде mysql:
   
   6.1 создание базы данных (имя должно совпадать с указанным в ya_hub.conf)
   Команда: create database your_database;
   
   6.2. создание пользователя (с логином и паролем, как указано в ya_hub.conf)
   Команда: create user 'your_user'@'%' identified by 'your_password';
   
   6.3. Предоставление прав пользователю
   Команда: grant all privileges on your_database.* to 'your_user'@'%';
   
   6.4. Импорт таблиц из шаблона
   Команда: source путь_к_ya_hub.sql;
   
   Будет импортировано 1 устройство в качестве примера интеграции с HomeAssistant,  а также таблицы sb_*, они содержат базовые настройки для работы со смартапом от Сбера и универсальным навыком Алисы. Их нужно модифицировать/расширить под свою реализацию смартапа/навыка и ваши id устройств непосредственно в базе данных. Или ничего не делать, если не будете использовать эти навыки. 
8. Сборка шлюза. При использовании более новых версий Wt и xdevapi вполне могут возникнуть проблемы. В каталоге ya_hub с исходными файлами выполнить:
   
   mkdir build && cd build

   cmake -DCMAKE_BUILD_TYPE=Release ..  (Или Debug для отладочной версии)
   
   make
   
   В случае успеха будет создан исполняемый файл ya_hub. В том же каталоге, что и исполняемый файл, должен лежать конфигурационный файл ya_hub.conf, каталог css и sh-файл отправки email, имя которого настроено в ya_hub.conf.
9. Создание первого и единственного пользователя: ./ya_hub -n login pass email. Не путать с пользователем базы данных. С этим login будет проходить связывание акаунтов и собственно работа с вводом описаний устройств.
Через интерфейс шлюза на текущий момент пользователя добавить нельзя. Несмотря на наличие необходимых элементов управления на экранных формах, сама возможность отключена в коде. Через командную же строку можно добавлять пользователей. Все они будут суперюзеры (администраторы с полными правами и уже активированные).
10. Запуск и ввод описаний устройств. Регистрация сервиса в systemd, вручную. Проброс портов, при необходимости, для доступа извне.
Запуск осуществляется просто: ./ya_hub. Или, если конфигурационный файл лежит где-то еще, так: ./ya_hub -c путь_к_конф_файлу. Ключ -s отключает вывод сообщений на экран.
После рабочего запуска интерфейс будет доступен по адресу, настроенному в ya_hub.conf
11. Создание навыка типа умный дом в экосистеме Яндекса. Связывание учетной записи Яндекса с сервисом. См. документацию Яндекса.
12. Отправка описаний устройств из интерфейса шлюза в Яндекс. Кнопка на форме редактирования устройства.
13. Дополнительные настройки умного дома Яндекс: уточнение имен, распределение по домам, сценарии, предоставление доступа дружественным акаунтам и т.д. Пояснения выходят за рамки статьи.
14. Готово.

Замечание 1. Шлюз должен уметь отправлять письма. Во-первых для ежеполуночного отчета о своей работе. Во-вторых (это пока неактуально) при регистрации пользователя или смене пароля. Делается это внешним вызовом, команда которого настраивается в ya_hub.conf. В примере настроен sendemail.sh, в котором нужно исправить свои почтовые параметры.

Замечание 2. Умный дом VK с Марусей настраивается аналогично, но с учётом отличий интерфейса приложений VK. На момент написания VK не имел url для отправки статуса и запроса на обновление устройств. Это компенсируется регулярными опросами со стороны самого VK.

Замечание 3. Настройка универсального навыка Алисы/смартапа Салюта может пригодиться в следующих случаях:
1) Навык умный дом не распознает какие-либо команды, специфичные для вашего умного дома.
2) Если вы хотите быть уверены, что голосовой помощник вернет именно то, что измерено вашим умным домом.
3) Если вообще нет возможности создать навык типа «умный дом» у провайдера голосового помощника.
Логика работы шлюза с универсальным навыком описана в конце статьи. Настройка же самого навыка выходит за рамки статьи.
